## A local decision point

Jevalan runs alongside your tools. It centralizes access to models and local policies, and lets you observe traffic in a terminal interface.

<CardGrid>
  <Card title="Compatible proxy">
    Forward System One requests to the backends you configure while preserving the contract between the agent and service.
  </Card>
  <Card title="Typed flows">
    Define decisions in YAML, combine rules and questions, and declare routes for results and errors.
  </Card>
  <Card title="Capability hub">
    Expose reusable decisions such as `agent.wakeup` or `tool.risk` through a local API.
  </Card>
</CardGrid>

## How it works

```text
Agent → local Jevalan → backend or flow → typed response → Agent
```

Jevalan does not run the command or apply the change. It returns a decision; the agent stays in control of what happens next.

## Try the demo

The demo uses mock services and reproducible traffic. It needs no keys and does not call external providers:

```sh
jevalan tui --demo
```
